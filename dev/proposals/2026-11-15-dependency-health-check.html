dracory/auth — proposal

Startup Dependency Check — Ping the Critical Callbacks

Status: Proposed Date: 2026-11-15 Scope: types, constructors, docs Inspired by: MadAppGang/identifo — connection_tester.go
⚠ POSSIBLY NOT NEEDED — thin library value (2026-11-15)
FuncHealthCheck is a passthrough: the library cannot probe opaque host callbacks, so this adds little a host couldn't do in main() — call its own ping functions and log.Fatal. The only real addition is the /api/auth/health endpoint, which is ~20 lines the host can also write itself. Build only if a concrete consumer needs the mounted endpoint.

Motivation

identifo runs a connection tester at boot: it probes storage and mail transport so a broken dependency fails the deploy at startup — visibly in logs — instead of failing the first real login attempt in production.

dracory/auth is callback-driven, so "dependencies" are the host's functions: user store, auth-token store, email sender, temporary-key store. A host whose DB or mail provider is down currently discovers it on the first POST /api/login.

Design

1. Optional health-probe callbacks

// types/config_health.go
type ConfigHealth struct {
    // FuncHealthCheck probes host dependencies at startup. Optional.
    // Return nil when healthy; the error is surfaced by CheckDependencies.
    FuncHealthCheck func(ctx context.Context) error
}

Rather than the library inventing probes for callbacks it cannot introspect, the host supplies one function that pings whatever it wired in (DB pool, SMTP, KV store). Keeps the library dependency-free.

2. Explicit check, not automatic

auth, err := NewUsernameAndPasswordAuth(cfg)
if err != nil { log.Fatal(err) }

// Optional — host decides when/whether to probe:
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
if err := auth.CheckDependencies(ctx); err != nil {
    log.Fatal("auth dependencies unhealthy: ", err)
}

Deliberately not automatic in the constructor: the library must never block or do network I/O unexpectedly, and tests must construct instances without live dependencies.

3. Readiness endpoint

When ConfigHealth.Enabled and the endpoint is mounted, expose GET /api/auth/health (unauthenticated, rate-limited) returning 200 {"status":"ok"} or 503 with no internal detail — for load-balancer/orchestrator readiness probes.

Security

  • Health endpoint returns no dependency names, versions, or error details
  • Rate-limited to prevent use as a cheap ping/oracle
  • CheckDependencies is never invoked implicitly — no surprise I/O

Out of Scope

  • Per-callback probing interfaces (e.g. requiring Ping() on stores) — callbacks are opaque funcs, not interfaces
  • Periodic re-checks / circuit breakers — host orchestration territory
