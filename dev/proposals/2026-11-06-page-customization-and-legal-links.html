dracory/auth — proposal

Per-Page Options & Legal Links

Status: Proposed Date: 2026-11-06 Scope: types, internal/ui/page_*, internal/ui/shared

Motivation

The built-in pages ship fixed copy — "Login to your account", "Send me a login code", "Don't have an account? Register". The package is consumed by multiple projects, and each project has its own voice: one wants "Welcome" / "Send login link", another wants formal wording, a third wants localization. Today the only escape hatch is replacing a whole page via the method constructors' page-builder slot — hundreds of lines to change a sentence.

Two additions close the gap without forking pages:

  1. Per-page customization structs — a *PageOptions type per built-in page (title, subtitle, field labels/placeholders, button and footer text). Named options rather than text so non-copy knobs (icons, extra links, card CSS class, injected HTML) can be added later without renaming.
  2. Global legal links — Terms of Use and Privacy Policy URLs on ConfigShared, rendered as the familiar "By continuing, you agree to …" line under the form. Links are site-level, identical on every auth page, so they live globally rather than per page. Each link is a struct carrying label, URL, and open behavior (same tab / new tab / modal).

Design Rules

  • Zero value = today's copy. Every field falls back to the current built-in string when empty. Fully additive: existing consumers are unaffected and never break when the package later adds a field or a page.
  • Bounded surface. Fixed fields per page — no map[string]string. The contract stays stable and greppable.
  • Brand stays global. BrandName / BrandTagline / BrandLogoURL remain site-level alongside ThemeCSS / CustomCSS / LoginAlternatives. Page customization does not duplicate them.
  • One flat struct per page. Copy fields live directly on *PageOptions; future non-copy fields join the same struct and are named distinctly.

Proposed Changes

1. Page Options Types (types/options.go)

// LoginPageOptions customizes the built-in login page.
// Zero value = package defaults.
type LoginPageOptions struct {
    Title               string // "Login to your account"
    Subtitle            string // method-appropriate default
    EmailLabel          string // "Email"
    EmailPlaceholder    string // "you@example.com"
    PasswordLabel       string // "Password" (password method only)
    PasswordPlaceholder string
    RememberMeLabel     string // "Remember me on this device"
    SubmitLabel         string // "Sign in" / method default
    ForgotPasswordLabel string // "Forgot password?"
    FooterPrompt        string // "Don't have an account?"
    FooterLinkLabel     string // "Register"
    // future: IconClass, CardClass, FooterLinks, ExtraHeadHTML, ...
}

type RegisterPageOptions struct {
    Title, Subtitle       string
    FirstNameLabel        string
    LastNameLabel         string
    EmailLabel            string // "Email (verified)"
    SubmitLabel           string // "Create account"
    FooterPrompt          string // "Already have an account?"
    FooterLinkLabel       string // "Login"
}

type CodeVerifyPageOptions struct {
    Title, Subtitle  string
    CodeLabel        string // "Code"
    SubmitLabel      string // "Verify"
    ResendLabel      string
    WrongEmailPrompt string // "Wrong email?" link label
}

type MagicLinkPageOptions struct {
    Title, Subtitle      string
    EmailLabel           string
    EmailPlaceholder     string
    SubmitLabel          string // "Send me a magic link"
    FooterPrompt         string
    FooterLinkLabel      string
}

type PasswordRestorePageOptions struct {
    Title, Subtitle  string
    EmailLabel       string
    SubmitLabel      string // "Send reset link"
}

type PasswordResetPageOptions struct {
    Title, Subtitle      string
    NewPasswordLabel     string
    ConfirmPasswordLabel string
    SubmitLabel          string // "Reset password"
}

type LogoutPageOptions struct {
    Title       string // "Logged out"
    Message     string
    SubmitLabel string // "Login again"
}

2. Config Fields (types/config_shared.go)

type ConfigShared struct {
    // ... existing fields ...

    // Page customizations — empty fields fall back to package defaults.
    LoginOptions            LoginPageOptions
    LoginOtpOptions         OtpPageOptions
    LoginCodeVerifyOptions  CodeVerifyPageOptions
    RegisterOptions         RegisterPageOptions
    RegisterCodeVerifyOptions CodeVerifyPageOptions
    MagicLinkOptions        MagicLinkPageOptions
    PasswordRestoreOptions  PasswordRestorePageOptions
    PasswordResetOptions    PasswordResetPageOptions
    LogoutOptions           LogoutPageOptions

    // Legal links rendered as "By continuing, you agree to {Terms} and
    // {Privacy}." under the form. Empty URL hides that clause.
    Terms   LegalLink
    Privacy LegalLink
}

CodeVerify is split into login/register variants — the two pages share the component but projects commonly want different subtitles ("enter the code we sent" vs "confirm your email to finish signing up").

3. Legal Links (types/legal_link.go)

type LinkTarget string

const (
    LinkTargetSameTab LinkTarget = "_self"
    LinkTargetNewTab  LinkTarget = "_blank"
    LinkTargetModal   LinkTarget = "modal"
)

// LegalLink configures a Terms/Privacy link: label, destination, and how
// it opens. Reusable for future link slots (FooterLinks, alternatives).
type LegalLink struct {
    Label  string     // default "Terms" / "Privacy Policy"
    URL    string     // empty hides the clause
    Target LinkTarget // default LinkTargetSameTab
}

modal renders an iframe inside a dialog (Notiflix is already a page dependency). Caveat, documented: framing requires the target page to permit it — X-Frame-Options and CSP frame-ancestors on the host site can block the modal; consumers choosing modal must serve frameable legal pages.

4. Page Plumbing (internal/ui/page_*)

No markup changes — every customized string already flows through a parameter: shared.PageHeader(title, subtitle), shared.FieldGroup(label, input), shared.PrimaryButton(...), shared.FooterText(prompt, url, label). Each page's content function gains a *PageOptions parameter (nil → defaults) resolved through one helper:

// internal/ui/shared/copy.go
func OrDefault(override, fallback string) string {
    if override == "" { return fallback }
    return override
}

The legal line renders once in shared, appended to the form card on login/register-type pages:

// shared.LegalLine(terms, privacy) →
// "By continuing, you agree to <a>Terms</a> and <a>Privacy Policy</a>."

5. Setters (types.AuthSharedInterface impls)

Optional setter interface alongside the existing SetBrandName / SetLoginAlternatives, so host apps push customization without reaching into config internals:

SetLoginPageOptions(LoginPageOptions)
SetPageOptions(PageOptions) // struct-of-structs, one call

Out of Scope (v1)

  • Alert/error message overrides — those strings are produced by the API handlers and shown via alert-group; customizing them is a separate, larger pass across internal/api
  • Email copy (OTP code email, magic-link email bodies) — owned by the mailer config, not the page layer
  • Full i18n plumbing (locale detection, per-request copy selection) — the structs are i18n-ready but selection stays the consumer's job
  • Per-page legal-link overrides (e.g. hiding the line on logout) — global only in v1; add HideLegal bool to customization later if a consumer asks

Compatibility

Purely additive: new types, new optional config fields, new optional setter methods behind an interface check. No signature changes to existing public functions (content builders gain parameters, but they are internal/ui, not exported API). Ships as a minor version.
