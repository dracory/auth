dracory/auth — proposal

OIDC / OAuth2 Social Login Method

Status: Proposed Date: 2026-11-02 Scope: types, internal/api, internal/ui/page_register, constants.go

Motivation

Social/OAuth login is the library's most-cited gap vs peers — the docs/peers/ comparisons repeatedly flag "Social / OAuth providers: only via AuthKnight" and "Enterprise SSO (SAML, OIDC): none". AuthKnight covers it only through a hosted third-party service; a project that wants "Sign in with Google" without an external dependency must hand-roll OAuth2 config, state/nonce validation, code exchange, JWKS verification, and the register-with-verified-email handoff — several hundred lines of security-sensitive code per project, per provider.

The types.Method contract was designed for exactly this extension ("projects can register TOTP, WebAuthn, OAuth, etc. methods without forking the library"), and the AuthKnight callback already implements the hard half: find-or-create by verified email, temp-key handoff to the register page, session creation. OIDC generalizes that pattern to any provider.

Flow

Standard authorization-code flow:

  1. App redirects the user to the provider's authorization endpoint with client_id, redirect_uri, scope=openid email profile, CSRF state, and nonce
  2. User authenticates at the provider
  3. Provider redirects back to redirect_uri with code and state
  4. App validates state, exchanges code for tokens (confidential POST with client_secret)
  5. App verifies the id_token (JWKS signature, iss/aud/exp/nonce) and extracts the verified email
  6. Existing user: session + auth cookie + success redirect
  7. New user: verified email → FuncTemporaryKeySet (1h), redirect to PathRegister with read-only pre-populated email + first/last name form — identical to the AuthKnight ak_key handoff
Steps 5–7 are exactly the existing AuthKnight post-verification path.

Library Choice

LibraryRoleNotes
github.com/zitadel/oidc recommended Full RP (discovery, code flow, token verification) and OP Certified by the OpenID Foundation (passes the official OIDC conformance suite for the relying-party profiles). Certification materially de-risks the token-verification path, the most security-critical code in this feature. One dependency covers the whole flow, and the OP side leaves the door open to dracory/auth acting as an IdP later. Cost: heavier dep tree than the alternative.
golang.org/x/oauth2 + github.com/coreos/go-oidc/v3 Code flow + id_token verification Lighter and the de-facto combo, but go-oidc is not conformance-certified and the pair requires wiring two libraries together.
Recommendation: zitadel/oidc. For a security feature, a conformance-certified verifier is worth the extra transitive deps. Its RP package (pkg/client/rp) also ships built-in state/nonce/PKCE helpers that match this design directly.

Proposed Changes

1. New Config: types.ConfigOIDC

type ConfigOIDC struct {
    ConfigShared
    ConfigRateLimiting
    ConfigCSRF
    ConfigImpersonation

    // ProviderName is the method slug used in routes, e.g. "google". Required.
    ProviderName string
    // ProviderLabel is the button label, e.g. "Continue with Google".
    // Defaults to "Continue with " + ProviderName.
    ProviderLabel string

    // IssuerURL enables OIDC discovery (e.g. "https://accounts.google.com").
    // If empty, the provider is treated as plain OAuth2 and Endpoint +
    // FuncEmailFromUserInfo are required.
    IssuerURL    string
    Endpoint     *oauth2.Endpoint // optional override / non-OIDC provider
    ClientID     string           // Required
    ClientSecret string           // Required
    Scopes       []string         // Defaults to ["openid","email","profile"]

    // FuncEmailFromUserInfo extracts a verified email for non-OIDC
    // providers (e.g. GitHub /user/emails). Required when IssuerURL is empty.
    FuncEmailFromUserInfo func(ctx context.Context, client *http.Client) (string, error)

    // User resolution — same contract as ConfigAuthKnight
    FuncUserFindByEmail func(ctx context.Context, email string, options UserAuthOptions) (userID string, err error)
    FuncUserRegister    func(ctx context.Context, email, firstName, lastName string, options UserAuthOptions) (userID string, err error)
    FuncRedirectURL     func(ctx context.Context, userID string) string

    HTTPTimeout time.Duration // Defaults to 10s
}

2. Method Factory: NewOIDCMethod

Unlike NewAuthKnightAuth (a standalone auth instance), OIDC is designed to be one types.Method among several — projects typically offer password/OTP plus Google/GitHub:

func NewOIDCMethod(config types.ConfigOIDC) (types.Method, error)
types.Method memberImplementation
Name()config.ProviderName
AlternativeLabel()config.ProviderLabel
PageHandler()GET → generate state+nonce, store via FuncTemporaryKeySet, 302 to provider auth URL (PKCE S256)
AjaxHandler()nil — redirect-based, like authknight
CallbackRoute()"GET /oidc/{provider}/callback"

3. New Handler: internal/api/api_oidc_callback/

  1. Extract state, code, error from the query
  2. Validate state (single-use, CSRF)
  3. Exchange code via zitadel rp.CodeExchange (honors HTTPTimeout)
  4. OIDC: verify id_token via zitadel rp.VerifyTokens (JWKS, iss/aud/exp/nonce) → verified email claim; plain OAuth2: FuncEmailFromUserInfo with token client
  5. Reject empty/unverified email
  6. Exists → auth token + FuncUserStoreAuthToken + cookie + success redirect; new → FuncTemporaryKeySet + PathRegister?oidc_key=

4. Shared Post-Auth Extraction

Extract the post-verification tail of apiAuthKnightCallbackPostAuth into a shared helper (e.g. internal/api/postauth/) used by both AuthKnight and OIDC — provider code ends at "produce a verified email". The register page's ak_key branch generalizes to also accept oidc_key (or unify under one param name at implementation time).

Security

  • state and nonce: cryptographically random, single-use — mandatory
  • PKCE (S256) on by default
  • Only email_verified=true claims / provider-verified emails accepted
  • Access/refresh tokens discarded after email resolution (no storage v1)
  • Callback endpoint under ConfigRateLimiting

Dependencies

github.com/zitadel/oidc/v3   (OpenID Foundation certified)
golang.org/x/oauth2          (pulled transitively; used for Endpoint type)

Out of Scope (v1)

  • OIDC provider mode (acting as an IdP) — zitadel/oidc's OP side makes this feasible as a follow-up without changing dependencies
  • SAML / LDAP enterprise SSO
  • Provider token persistence / calling provider APIs post-login
  • Account linking UI (v1 matches on verified email only)
