dracory/auth — proposal

Fail-Fast Config Validation — Validate() at Construction

Status: Proposed Date: 2026-11-15 Scope: types, all new_*_auth.go constructors Inspired by: MadAppGang/identifo — server_settings_validation.go, configuration_watcher.go

Motivation

identifo validates its entire server settings tree centrally at startup and fails loudly on misconfiguration. dracory/auth's config surface has grown — ConfigShared, ConfigRateLimiting, ConfigCSRF, ConfigImpersonation plus method-specific callbacks across new_otp_auth.go, new_username_and_password_auth.go, and new_authknight_auth.go. Missing a required callback currently surfaces as a nil-pointer panic at request time, not at boot.

Typical foot-guns a Validate() catches:

  • OTP/magic-link enabled but FuncEmailSend nil
  • Code TTL > 24h or code length < 4
  • Impersonation enabled without FuncUserFindByID
  • CSRF disabled together with cookie-based endpoints in production
  • Rate limiting enabled with zero/negative window

Design

1. Per-struct Validate()

// types/config_shared.go
func (c ConfigShared) Validate() error {
    var errs []error
    if c.FuncUserStoreAuthToken == nil {
        errs = append(errs, errors.New("auth: ConfigShared.FuncUserStoreAuthToken is required"))
    }
    if c.FuncUserFindByAuthToken == nil {
        errs = append(errs, errors.New("auth: ConfigShared.FuncUserFindByAuthToken is required"))
    }
    // ...
    return errors.Join(errs...)
}

2. Constructors fail fast

func NewUsernameAndPasswordAuth(config ConfigUsernameAndPassword) (*Auth, error) {
    if err := config.Validate(); err != nil {
        return nil, fmt.Errorf("auth: invalid config: %w", err)
    }
    // ...
}

errors.Join reports all problems at once — the developer fixes the whole list in one pass rather than iterating panic-by-panic.

3. Warnings vs errors

Some misconfigurations are suspicious but legal (e.g. CSRF disabled for a pure-API deployment). Return them from a separate method so constructors can log them via slog without failing:

func (c ConfigShared) Validate() error    // hard errors — constructor returns nil
func (c ConfigShared) Warnings() []string // logged at construction

Compatibility

Constructors already return error, so the signature is unchanged. The only behavioral difference: previously-invalid configs now fail at boot rather than at first request — strictly better.

Out of Scope

  • Hot-reload / config watchers (identifo's configuration_watcher) — Go services reload config by restarting; not needed
  • Cross-method validation in NewMultiMethodAuth is included only where one method depends on another's callback
