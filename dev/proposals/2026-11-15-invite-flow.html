dracory/auth — proposal

User Invitation Flow — Invite Email → Set Password

Status: Proposed Date: 2026-11-15 Scope: types, internal/api, internal/ui, internal/emails Inspired by: MadAppGang/identifo — invite.go
⚠ CONSIDER ALTERNATIVES — possible duplication of register machinery (2026-11-15)
Before building three new endpoints, check whether invite can be a configuration of the existing register/verified_key flow (a verified_key carrying pre-set attrs, a register page variant) rather than a parallel provisioning path duplicating token store, email and acceptance logic. Also note: POST /api/auth/invite as specified performs no authorization — a fail-open default if the host forgets to wrap it; require an explicit authorize callback or let the host mount the handler.

Motivation

identifo ships an invitation flow: an administrator (or host code) creates an invite for an email address; the recipient clicks a link and completes their account by setting a password. This is a common enterprise/B2B need — "we created your account, please activate it" — that public self-registration does not cover:

  • Accounts provisioned before the user exists (staff onboarding, migrated users)
  • Invite-only products where open registration stays disabled
  • Pre-assigned attributes (role, tenant, plan) that the user must not choose

dracory/auth currently has no equivalent; host apps reimplement it on top of password-restore or register endpoints.

Design

1. Config

// types/config_invite.go
type ConfigInvite struct {
    Enabled            bool
    InviteTokenTTL     time.Duration // default 72h

    // FuncUserInvite persists an invite: email + optional pre-set attributes
    // (opaque map passed through to FuncUserRegister on acceptance).
    FuncUserInvite        func(ctx context.Context, email, token string, attrs map[string]string, expiresAt time.Time) error
    FuncUserInviteFind    func(ctx context.Context, token string) (email string, attrs map[string]string, err error)
    FuncUserInviteDelete  func(ctx context.Context, token string) error
    FuncUserFindByEmail   func(ctx context.Context, email string) (userID string, err error)
    FuncEmailSend         func(ctx context.Context, email, subject, body string) error
}

2. Endpoints

  • POST /api/auth/invite — authenticated (admin-side middleware responsibility of the host); creates an invite, sends the email
  • GET /register?invite=TOKEN — register page variant with email read-only and a "set your password" framing; reuses the existing register page structure
  • POST /api/auth/invite/accept — validates the token, calls FuncUserRegister with the invite's pre-set attributes merged in, deletes the invite, logs the user in

3. Flow

  1. Host/admin calls POST /api/auth/invite with email + attrs
  2. Library stores the invite and emails a link ({appURL}/register?invite=TOKEN)
  3. Recipient opens the link — email is locked, supplies name + password
  4. invite/accept creates the user with the invite attrs, deletes the token (single-use), issues the session

Security

  • Invite tokens: 256-bit random, single-use, TTL-bounded
  • Accept endpoint under ConfigRateLimiting and ConfigCSRF
  • POST /invite performs no authorization itself — the host wraps it in its admin middleware (documented requirement)
  • Inviting an already-registered email returns a generic success response (no account-existence enumeration)

Out of Scope (v1)

  • Bulk/CSV invites, invite management UI (list/revoke) — host admin territory
  • Org/team-scoped invites (attrs is opaque, so a host can encode tenant IDs)
  • Re-send/reminder scheduling
